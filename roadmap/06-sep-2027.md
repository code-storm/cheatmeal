# September 2027 — H2 Phase 5: Pre-festival-event push; native build month 2; content trust pass

**Theme:** finalize the October branded event, apply a trust pass to new content, and — on Track B — continue the native build.

## Carried-forward risk check-in

Retention assumption validation closes a loop this month on Track B: push notifications (see below) are the most direct, evidence-based answer to the retention fragility H1 flagged from day one.

## Track A — still solo/bootstrapped

- **Apply the `source`-citation trust pattern** H1 Phase 2 gave avoid-rules to the new postpartum content — newborn-care claims need the same "why this is on your list" surfacing, arguably more so given the content is outside the original pregnancy-week domain. A direct lift-and-apply of an existing H1 pattern into new content, not a new UI concept.
- **Finalize the branded/seasonal event** sourced in August for an October launch (Diwali-timed, mirroring H1 Phase 5's Holi-timed event logic).
- **Continue light social:** extend Bump Squad cohorts to also work across the pregnancy→postpartum transition — a cohort shouldn't dissolve the day a user's due date passes. A cheap, direct link between the content-expansion and light-social workstreams.

## Track B — if team/funding grows

- **If native build is underway:** build-month-2 — reward/event/cosmetic-shop flows, plus push-notification wiring. This is genuinely only viable well on native, unlike PWA — the clearest concrete "why native" payoff in the whole plan. Target a Play Store submission in October.
- Same trust-pass and cohort-continuity work as Track A, with the cadence advantage of doing both in parallel where Track A has to sequence them.

## Metrics

Track A: **~1,700–2,100 WAU**. Track B: **~2,000–3,000+ WAU** — push notifications, if live even in beta/submitted-app form, are the single biggest retention lever introduced in H2, which is why Track B's range widens specifically here, not generically.
